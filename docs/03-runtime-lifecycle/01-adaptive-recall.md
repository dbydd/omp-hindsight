# 自适应 Recall：长程自治工作流下的动态 Skill 注入与防抖

在真实的工程开发场景中，编码助手绝大多数时间处于**长程自治推进状态**。当人类用户给出一条初始任务后，助手会连续调用工具进行代码查阅、编辑、编译测试与调试排错，期间数十轮交互均没有新的人类用户输入。

本篇文档详细阐述系统如何通过自适应上下文提取器（Adaptive Context Extractor），在自治循环中为助手动态注入即时技能提示（In-context Skills）。

---

## 传统固定抓取 User 消息的失效分析

早期系统将自动 Recall 简单定义为“提取最近两轮的 `user` 角色消息拼接为检索词”。在编码助手的自治推进中，该模式暴露出两大致命缺陷：

1. **检索焦点严重滞后（刻舟求剑）**：
   用户第一轮输入的指令往往非常宏观（例如“重构用户权限模块并跑通单元测试”）。当助手自主推进到第 7 轮，深陷“处理某一特定加解密库在 arm64 架构下的符号链接冲突”时，固定检索逻辑仍在向记忆库发送“重构用户权限模块”，完全无法命中该加解密库的历史踩坑记录。
2. **动态规约与技能注入完全瘫痪**：
   Hindsight 中沉淀着项目团队建立的结构化规约（`knowledge:convention`）与历史架构决策（`knowledge:decision`）。只有当记忆系统感知到助手当前准备操作哪一个具体文件、修改哪个组件、遇到了什么错误时，这些规约才能像动态挂载的技能（Skills）一样精准投送到上下文提示中。

---

## 自适应上下文提取器的工作机制

系统引入自适应提取器，在每一轮模型即将发起推理的前置钩子（`before_provider_request`）中运行：

```
[ 最近 N 轮消息窗口 (user, assistant, tool) ]
                      │
                      ▼
        【自适应上下文提取器】
   ┌──────────────────┴──────────────────┐
   ▼                                     ▼
[ 报错优先通道 ]                      [ 自治意图通道 ]
- 抓取非零退出码与 stderr 报错        - 提取助手的 Plan / Sub-goal
- 提取异常签名 (如 ORA-01461)         - 提取当前操作的目标模块与路径
   └──────────────────┬──────────────────┘
                      ▼
               [ 噪音彻底过滤 ]
        - 剥离大段代码 diff 与二进制日志
        - 仅保留核心语义骨架与错误指纹
                      │
                      ▼
               [ 双通道定向检索 ]
        - 检索事实 (facts)
        - 定向召回规约 (knowledge:convention/decision)
                      │
                      ▼
            [ 焦点位移防抖判断 ]
   - 比较最近操作对象是否发生位移？
   - 连续在同一文件微调且无新报错 → 跳过刷库
                      │
                      ▼
         [ 动态 Skill 临时消息注入 ]
```

### 1. 扫描角色窗口放宽（`recallContextRoles`）
配置项 `recallContextRoles` 默认放宽为 `["user", "assistant", "tool"]`。提取器向前回溯最近 `recallContextTurns`（默认 2）轮消息。

### 2. 报错优先通道（Error-first Heuristics）
若最近的消息包含工具执行失败记录（例如 Bash 执行退出码非零，或 stderr 包含错误栈）：
- 提取器立即激活报错通道，提取错误的核心指纹（例如 `VectorChord dimension overflow` 或 `Segmentation fault at 0x7fff`）以及发生错误的文件路径。
- 该指纹直接构成检索的主关键词，用于在记忆库中精准召回先前关于该类异常的修复方案。

### 3. 自治行动意图通道（Plan & Intent Mining）
若当前处于连续的助手自主操作流：
- 提取器分析助手的文本陈述，抓取位于段落开头、带有明确行动导向的意图陈述句（Sub-goal，例如“正在为数据同步模块添加原子锁”）。
- 同时提取最近调用的工具所指向的目标实体（例如正在编辑的文件名、正在测试的函数名）。

### 4. 噪音过滤机制
长程编码任务中充斥着大段的代码 diff、数据 dump 与十六进制内存日志。若直接拼接入检索词，会使向量检索与 BM25 检索严重失真。提取器在构建检索词前强制剥离所有代码围栏块（` ``` `），仅保留诊断语句与语义主干。

## 动态 Skill 注入形态与提示词围栏

提取器合成检索词后，向 Hindsight 发起查询，重点召回打有 `knowledge:convention` 和 `knowledge:decision` 标签的知识页与观察记录。

检索结果作为一条临时的 `user` 角色消息注入到当下的推理上下文前部。消息采用显式的围栏格式封装，并附带针对性的系统前言：

```markdown
<hindsight_memories>
[System note: The following context guidelines and project skills were surfaced from Hindsight based on your current execution focus. Use them to guide your next action; prioritize recent when conflicting; ignore irrelevant entries:]

- 【规约】关于向量索引配置：在 arm64 架构下必须显式开启 HNSW_M48 编译开关。
- 【历史决策】数据同步管道避免在主线程中调用全量 upsert，推荐使用轻量级 pending marker 机制。
</hindsight_memories>
```

- **注入内容完全临时**：该消息不写入本地的会话存储文件，保证会话文件的纯净，并最大程度利用大模型接口的提示词缓存（Prompt Caching）。
- **围栏前言杜绝反馈污染**：前言明确告知模型这是背景参考知识，防止模型误将其当成人类用户的最新操作指令。

## 焦点防抖（Debounce）与失败降级

为了避免在高速工具循环中无谓消耗算力与网络带宽，系统设立了两道保障机制：

1. **焦点位移防抖（`recallDebounceTurns: 3`）**：
   若助手在连续 3 轮交互中均在同一个源文件内进行微小的语法修补，且期间没有产生任何新的报错，系统判定“当前上下文无实质位移”。提取器自动跳过本轮检索，沿用上一轮注入的知识或保持静默，避免高频刷库打扰模型的注意力。
2. **失败静默降级（Failure Fallback）**：
   检索超时时间设定为 `recallTimeoutMs: 10000`（10 秒）。一旦遇到网络超时或 Hindsight 实例暂时不可达，系统立即静默降级为本轮无记忆注入，并在后台记录一条诊断日志，坚决不阻断 Agent 的正常编码执行。
