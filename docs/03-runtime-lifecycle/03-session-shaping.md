# 知识与决策沉淀纪律：拒绝聊天流水账，聚焦高质量经验

在明确了“过程归 `history://`，知识归 Hindsight”的初心之后，系统彻底禁止将未经提炼的聊天流水账自动倾倒进记忆库。

记忆库只接纳高价值的结构化资产：通过受控管道入库的研究文献、由人类或 Agent 显式确认的架构决策（Decisions）、团队达成的工程规约（Conventions）以及由决策评估器提炼的通用经验。

本篇文档阐明知识沉淀时的去噪纪律与严格的不变量要求。

---

## 清洗管道的处理流程

```
[ 原始会话 JSONL 文件 ]
          │
          ▼
【层次一：角色内容提取 (retainContent)】
  ├─ 提取 user 消息的文本正文
  ├─ 提取 assistant 的文本、推理过程 (thinking) 与工具调用声明
  └─ 提取 toolResult 的有效输出
          │
          ▼
【层次二：工具特征过滤 (toolFilter)】
  ├─ 排除只关心结果的读取调用 (grep, glob, read, find)
  ├─ 排除无结构的大段文件写入结果 (write, edit, apply_patch)
  └─ 绝对排除 hindsight 自家工具 (防记忆反馈环)
          │
          ▼
【层次三：机器元数据剥离 (strip)】
  └─ 剥除 usage, cost, provider, model, responseId, stopReason
          │
          ▼
[ 结构纯净的高价值会话材料，送入 Retain 异步分块 ]
```

---

## 核心纪律：彻底排除自家工具，切断记忆反馈环（Feedback Loop）
```jsonc
"alwaysExclude": ["hindsight"]
```
这是清洗规则中最关键的不变量：**严禁在记忆库中记录对 `hindsight` 工具自身的调用与返回结果。**

如果记录了对记忆工具的调用：
1. 记忆库会把“Agent 在第 3 轮调用了 `hindsight` 检索了关于缓存的配置”作为一条独立事实存入库中。
2. 在后续轮次中，当 Agent 再次搜索缓存配置时，检索算法会把先前这条“自己搜过某事”的历史记录重新召回。
3. 这种自我引用的内容会随着会话迭代被反复提取并无限放大，形成严重的“反馈环路（Feedback Loop）”，最终使记忆系统充斥着无用的检索元记忆。

---

## 层次三：机器元数据剥离（strip）

为了保证入库文本的语义纯粹度，清洗管道会递归遍历消息树，将所有由大模型网关或运行平台附加的机器属性全量剥除：

```jsonc
"strip": {
  "message": [
    "usage",        // token 消耗统计
    "cost",         // 计费数据
    "provider",     // 服务商标识 (如 deepseek, anthropic)
    "model",        // 底层模型版本号
    "responseId",   // 网关响应流水号
    "stopReason"    // 结束标记
  ]
}
```

### 剥除元数据的工程价值

1. **大幅提升模型接口的提示词缓存（Prompt Caching）命中率**：不同批次或重新加载的历史消息中，如果带有动态变化的流水号和时间戳，会导致哈希校验失效。剥除元数据后，清洗出的文本结构具备高度的确定性。
2. **保护隐私与凭据隔离**：避免运行时的具体供应商配置与内部网络路由信息被持久化进记忆库。
