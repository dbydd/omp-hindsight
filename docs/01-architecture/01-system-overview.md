# 系统整体架构总览

`hindsight-omp` 是专为 `oh-my-pi`（omp）开发的长程记忆插件。它将持久化的 Hindsight 记忆系统无缝接入编码助手的全流程工作流中。

## 系统的三大核心支柱

整个插件的架构围绕三个核心设计支柱建立：

```
                      +-----------------------------------+
                      |      oh-my-pi 宿主环境 (Tern)      |
                      +-----------------------------------+
                                        |
       +--------------------------------+-------------------------------+
       |                                |                               |
       v                                v                               v
[ 资源面：虚拟文件系统 ]       [ 操作面：单工具与判定网络 ]       [ 运行时：自适应生命周期 ]
- hindsight:// 虚拟挂载        - hindsight(intent, meta)       - 启动时全景常驻注入 (L1)
- 映射事实/文档/知识页/操作      - 42 个低分支选择题判定树         - 自治工作流自适应感知 (L2)
- 映射本地源码与测试文件        - 两阶段原文切片与无损装配        - 目录原子重命名持久队列
- Agent 用 read/grep 即可浏览   - 零文本二次改写与零参数幻觉      - 会话自动清洗与去噪防反馈
```

### 1. 资源面：可持久寻址的虚拟文件系统

传统记忆插件把所有结果局限在工具单次调用的文本返回值中。这种设计带来严重的生命周期缺陷：随着对话轮次推进，工具输出会被滚动滑窗移除或在会话压缩中丢失。

本插件通过注册 omp 的虚拟协议处理器，将远端记忆库完整映射为只读文件系统 `hindsight://`：
- 记忆库中的原始文档、分块（chunks）、事实（facts）、观察记录（observations）、知识页（knowledge pages）、心智模型（mental models）与最近操作记录全部拥有确定性的虚拟路径。
- Agent 可以直接使用其原生掌握的 `read`、`grep`、`find` 工具自由翻阅记忆库。
- 虚拟路径支持与本地工程中的实际文件建立双向映射，使文档中的引用直接指向真实的源码或论文文件。

### 2. 操作面：单工具入口与分层判定网络

为了避免在 Agent 的上下文窗口中平铺数十个专用工具造成的提示词膨胀与注意力混淆，系统将所有对外交互收敛为单个工具：

```ts
hindsight(intent: string, meta?: Record<string, unknown>)
```

在工具底层，系统部署了一个分层判定网络（Hierarchical Judge Network）：
- 接收自然语言意图，通过二叉或三叉的选择题逐步推导最终动作。
- 每个选择题具有互斥且完备的选项，彻底杜绝开放式自由生成。
- 参数提取采用两阶段物化机制：模型只标明参数在用户原句中的起止位置（span），由底层确定性代码从原始字符串中切片复制，杜绝了参数捏造与文本改写失真。

### 3. 运行时：自适应生命周期与高可靠队列

插件与 omp 的生命周期事件深度联动，提供全自动的记忆感知与持久化支持：
- **常驻层（L1）**：在会话启动时，将核心心智模型与知识树目录直接载入上下文，提供零延迟的基础共识。
- **动态感知层（L2）**：在 Agent 自主执行长程任务时，自适应提取器敏锐感知助手最新的报错信息、操作目标与子规划，动态提取并注入相关的工程规约（Conventions）与历史决策（Decisions），充当随需浮现的技能挂件。
- **高可靠写入队列**：会话的持久化与显式写入通过文件系统目录的原子重命名（Atomic Rename Claim）进行异步消费，保证宿主崩溃或网络中断时数据零丢失，并在服务恢复后无缝续传。

## 模块分层与依赖方向

系统在代码组织上严格遵循单向依赖原则，各层职责边界清晰：

```mermaid
graph TB
  subgraph Entry["入口层 (Entry)"]
    Runtime[运行时单例管理]
    ToolDef[hindsight 单工具注册]
    Protocol[hindsight:// 虚拟路径路由]
    SlashCmd[/hindsight 斜杠命令]
  end

  subgraph Adapter["宿主适配层 (Adapter)"]
    Lifecycle[omp 生命周期事件监听]
    TurnRecall[每轮自适应 Recall 注入]
    FlushHook[会话结束与压缩持久化钩子]
  end

  subgraph Core["核心逻辑层 (Core - 纯 TypeScript，零外部依赖)"]
    ConfigLoader[分层配置加载与校验]
    HttpClient[Hindsight OpenAPI 客户端]
    JudgeEngine[分层 Choice 判定与执行引擎]
    SlotAssembler[原文切片与两阶段装配器]
    DiskQueue[基于文件系统的持久化队列]
    Shaping[会话清洗、脱敏与去噪]
    PathResolver[虚拟路径到实体数据解析器]
  end

  Entry --> Adapter
  Adapter --> Core
  Entry --> Core
```

- **Core 模块完全无宿主依赖**：Core 内部不导入任何 `@oh-my-pi/pi-coding-agent` 的类型或包，可以在纯 Node.js 或 Bun 环境中进行 100% 的单元测试与确定性重放。
- **Adapter 模块专门负责生命周期转换**：将 omp 派发的 `session_start`、`context`、`agent_end`、`session_compact` 等事件转换为对 Core 模块标准接口的调用。
- **Entry 模块统一管理运行时状态**：以单例模式暴露插件实例，保证配置发生变更时整体重建，配置非法时静默降级而不破坏主程序。
