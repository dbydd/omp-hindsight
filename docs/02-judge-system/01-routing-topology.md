# 判定网络架构：从自然语言意图到原子动作的有限分支树

用户调用 `hindsight` 工具时，传入的是不可预测的自然语言意图字符串（`intent`）。系统的任务是将这一字符串准确转换为底层的具体 API 调用。

传统方案通常让大模型直接输出最终的动作枚举与参数。这种单步推理在面对 26 种细分动作时，极易混淆相似动作，产生参数幻觉。

本系统采用有向无环图（DAG）形式的分层判定网络。通过一组逐步递进的选择题，将复杂的语义判定拆解为确定性的有限推理链条。

---

## 判定网络的整体分层逻辑

判定过程按照客观执行所需的前置依赖关系，分为四个清晰的阶段：

```
用户输入自然语言 intent
      │
      ▼
【阶段一：请求结构分析】
  ├─ J0：单动作还是多动作？
  └─ J1：多动作之间是否存在顺序依赖？（若有多个动作，拆解为执行计划）
      │
      ▼
【阶段二：副作用分类】
  └─ J2：该动作是只读查询，还是产生持久化修改的写操作？
      │
      ├───────────────────────────────┐
      ▼                               ▼
【阶段三：只读通道特化】        【阶段三：写入对象特化】
  ├─ 检索原子事实 (recall)        ├─ 保存会话或事实 (retain)
  ├─ 跨文档深度合成 (reflect)     ├─ 知识页管理 (kb: create/update/delete)
  ├─ 知识库查询 (kb.search/get)   ├─ 心智模型维护 (mm: create/update/refresh)
  ├─ 心智模型读取 (mm.get)        └─ 运维动作执行 (ops: cancel/clear)
  └─ 任务与运维检查 (ops.get/list)    │
      │                               │
      └──────────────┬────────────────┘
                     ▼
【阶段四：目标消歧与两阶段参数物化】
  ├─ S0/S1：目标 Bank 与实体 ID 的确定性绑定（候选 ≤ 3）
  ├─ X1：仅提取参数在输入中的起止字符指针（span）
  └─ D2：底层代码直接切片装配，形成最终的执行参数
```

---

## 节点的三种物理形态

判定网络中的节点并非全部是大模型调用，而是根据计算性质严格区分为三类：

### 1. Choice 判定节点（前缀 J、R、W、S）
- **实现方式**：调用轻量级分类模型（`modelRoles.judge`）。
- **运行特征**：只回答一道严格的单选题。选项数为 2 到 4 个。
- **输出约束**：模型只能从预设的候选项代码中选择一个（例如输出 `"read"` 或 `"write"`），严禁输出任何多余的自由文本或参数值。
- **证据准则**：每个选项均定义了明确的“证据特征（criteria）”。模型依据输入文本中出现的具体动词和宾语进行归类。

### 2. 结构化提取节点（前缀 X）
- **实现方式**：调用当前会话的主模型执行严格的 JSON Schema 抽取。
- **运行特征**：仅在目标动作已经完全锁定的终点阶段调用一次。
- **输出约束**：模型只输出数值、布尔值以及文本在原句中的字符起止范围（`[start, end]`），绝对不生成改写后的业务正文。

### 3. 确定性执行节点（前缀 D）
- **实现方式**：由插件核心的 TypeScript 代码直接执行，**完全不调用任何语言模型**。
- **运行特征**：负责内存变量提取、权限前置检查、原始字符串切片以及对象组装。
- **典型节点**：
  - `D0`：接入层解析，登记输入文本的不可变哈希与长度。
  - `D1`：写准入安全检查，核实当前配置与目标 Bank 的写入权限。
  - `D2`：槽位组装，根据 X1 提供的指针，从内存中的原始输入复制纯净文本，组装成最终的 API 请求体。

---

## 异常阻断机制（unresolved）

在整个判定树的任何一个选择题节点中，除了 2 到 3 个业务选项之外，均内置了隐式的 `unresolved` 阻断分支。

当出现以下三种情况时，系统直接判定为 `unresolved`：
1. **证据不足**：输入表述过于抽象，无法支撑当前维度的分类决策（例如只输入了一个词“知识库”，无法判断是查询、创建还是删除）。
2. **证据冲突**：输入中同时包含了相互矛盾的指令特征（例如“删除旧内容并同时检索相关先例”在单个原子动作中冲突）。
3. **超出范围**：用户请求的动作不在系统当前支持的 26 个受控动作清单内。

当命中 `unresolved` 时，系统立即安全终止本次判定。判定引擎生成一条结构化的错误报告，指明在哪一个具体节点发生阻断，并列出缺失的关键证据，原样返回给调用方，坚决阻止大模型在含糊状态下强行猜测执行。
