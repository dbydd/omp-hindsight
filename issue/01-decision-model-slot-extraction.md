# ISSUE-01: 决策模型槽位提取失败导致心智模型与知识页无法按名创建

## 现象描述

在使用 `hindsight` 单一工具入口时，当用户通过自然语言明确表达创建实体并给出名称时，背后的意图判定与决策模型频繁无法抽取出 `name` 字段，抛出参数缺失错误中断流程。

同时，针对该错误的绕行方案在知识页与心智模型两个分支表现出不一致的行为。

---

## 典型复现用例与观测回执

### 用例 1：心智模型名称显式内嵌（四种自然句式全败）

| 序号 | 传入 intent 文本 | 工具回执与诊断 |
|---|---|---|
| 1.1 | `创建一个名为「工具面心得」的心智模型，用来沉淀 omp-hindsight 插件的使用经验` | 报错：缺少 name。没有给出心智模型名称 |
| 1.2 | `为 testrole 建立一个叫「工具面心得」的心智模型` | 报错：缺少 name。没有给出心智模型名称 |
| 1.3 | `用 mm.create 在 agent-testrole 建一个新心智模型，名称是「工具面心得」` | 报错：缺少 name。没有给出心智模型名称 |
| 1.4 | `创建心智模型：工具面心得`（附带 `target: hindsight://agent-testrole/mental-models/工具面心得`） | 报错：缺少 name。没有给出心智模型名称 |

### 用例 2：知识页名称内嵌与 target 路径绕行对照

| 序号 | 传入参数 | 工具回执与诊断 |
|---|---|---|
| 2.1 | `intent: 在 agent-testrole 知识库创建一页，页名：探索日志` | 报错：缺少 name。没有给出知识页名称 |
| 2.2 | `intent: 在 agent-testrole 的知识库创建一页「探索日志」` + `target: hindsight://agent-testrole/kb/pages/探索日志` | **成功创建**，页面 ID 为 `kp-21dd5105cb4b4ee3bb38ca3641de1f40` |

---

## 根因与机理分析

1. **槽位提取提示词覆盖不全**：决策模型在处理 `mm.create` 和 `kb.page_create` 分支时，依赖严格的键值对或特定模式匹配提取实体名称。当自然语言使用汉语常见的定语从句（「名为 X 的……」「叫 X 的……」）或冒号语法（「心智模型：X」）时，抽取逻辑失效。
2. **target 参数解析存在分支差异**：
   - 在 `kb` 分支中，适配层实现了从虚拟路径尾段解析页面名称的逻辑（`hindsight://.../kb/pages/<name>` 可以作为 `name` 的 fallback 来源）。
   - 在 `mental-models` 分支中，缺乏相同的尾段抽取与兜底逻辑，导致传入合规的 `target` 虚拟路径依然报错拦截。

---

## 影响评估

- 阻断了自动化 Agent 通过自然语言自主建立知识体系的能力。
- 迫使上层模型不断退回重试，消耗额外思考与交互轮次，甚至引发指令挫败。

---

## 修复建议

1. **增强判定模型 Prompt 槽位提取**：在 system prompt 中增加少样本示例（Few-Shot Examples），显式覆盖以下命名模式：
   - `名为/叫[做]?「?([^」]+)」?的(心智模型|知识页)` -> `name = $1`
   - `(心智模型|知识页)[:：]\s*([^\s]+)` -> `name = $2`
   - `名称[为是][:：]?\s*「?([^」]+)」?` -> `name = $1`
2. **对齐 target 虚拟路径的容错兜底**：在 `mm.create` 决策分发逻辑中，补充与 `kb.page_create` 一致的 fallback：当 intent 未抽取到 name 但 `target` 符合 `hindsight://<bank>/mental-models/<name>` 结构时，自动以末尾段作为实体名称。
