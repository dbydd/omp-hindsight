# ISSUE-10 · 系统元问题从向量检索解耦，直通资源树路由（待办）

- 状态：**待办（立项阶段，暂不实施）**
- 关联问题：ISSUE-07、ISSUE-08 (T1-11)、ISSUE-09 (T2-33)
- 涉及模块：SSOT `spec.ts`、`action_family`、`url.ts`

---

## 1. 现象与痛点描述

调用端 Agent 在日常交互中常常会问及插件系统本身的配置与元状态：
- 「判断意图所用的模型角色叫什么？」
- 「当前加载了哪些 memory banks？」
- 「重试队列积压了多少？」
- 「当前插件的超时时间和最大预算是多少？」

当前架构下，这类请求全部作为 `memory_query` 打入底层向量检索（recall）或 reflect 阶段。
这造成了三个结构性弊端：
1. **概率检索对抗确定性配置**：插件的配置与拓扑属于本地内存或配置文件的确定性事实，用自然语言向量相似度去搜，极易发生命中漂移或提取不到。
2. **产生无意义的网络开销与 Token 消耗**：一次问答需要经过 S1 模型判定 + 向量服务器网络往返，不仅耗时数百毫秒到数秒，还可能因为库里恰好存过类似讨论而提取出过期的历史配置。
3. **冷启动与未入库时的空窗**：在全新库或空库中，询问自身配置必然返回 0 命中或宽召回噪音。

---

## 2. 目标设计方案（下一阶段实现）

### 2.1 SSOT 操作目录与族系扩展
在 `spec.ts` 的 `ACTION_FAMILIES` 中增加一个只读族系：
- `system_meta`：系统元数据与插件状态直读。

### 2.2 动作映射与端点直连
在 `spec.ts` 登记确定性操作：
- `system_meta.config`：直通 `hindsight://plugin/config`。
- `system_meta.banks`：直通 `hindsight://` 根目录。
- `system_meta.queue`：直通 `hindsight://queue`。

### 2.3 执行层零网络开销返回
在 `ops.ts` 中拦截 `system_meta.*` 动作：
直接调用 `url.ts` 中现成的本地渲染函数（如 `configView`、`rootView`、`queueView`），生成确定性的标准回执与文本，无需向远端 Hindsight 实例发起任何向量检索请求。
