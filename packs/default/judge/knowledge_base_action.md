# Instructions
这一问已经确认用户在操作知识库的结构化资产（知识页与目录）。判断他要做的具体动作。

两个维度一起看：意图动词决定操作类型；目标是否已存在决定 create 与 update 的分野。state.focus.explicit_target 非空时，说明用户已经点名了具体页面或目录路径，这是「目标已存在」的强信号。

# Criteria

## tree
查看知识库的整体骨架：目录树、大纲、层级、文件夹清单。不指向某一篇具体页面，产出是结构而非正文。

## search
按主题或关键词寻找有哪些页面，但用户还不知道是哪一篇。产出是页面清单与摘要，不是某篇正文。

## get
读取一篇页面的完整正文，产出是那一篇的内容而不是清单。两种说法都算 get：
- 已点名页面：给了名称、别名、id，或 explicit_target 指向某页。
- 用单数指代要正文：「这篇知识页」「该页」「知识页的详情/正文/内容给我」「打开知识页看看内容」。即使没写页名，宾语也是某一篇页面的正文，具体是哪一篇由下游槽位解析。

与 search 的分界在产出：要某一篇的正文是 get；要「有哪些/哪些页/找几篇」这种候选清单才是 search。

## page_create
新建一篇此前不存在的页面。动词是「新建 / 创建 / 建一页」并给出新页标题。

整份论文或文档入库不属于此动作，那是 memory_retain；知识页是结构化 Wiki 节点，文档是物理入库材料。

## page_update
对一篇已存在页面做演进：改正文、改取材问题、改名、改归属或标签，以及「构建 / 重新生成 / 刷新 / rebuild / refresh / build」这篇已有页面的内容。

explicit_target 已指向某篇现有页面时，build/refresh/重生成都是对该页的 update，不会新建第二页。

## page_delete
删除一篇已存在的页面（连同其子树）。动词是「删除 / 移除 / 删掉」且宾语是页面。

## folder_create
新建一个用于分类的文件夹或目录节点，宾语是文件夹而非页面。

边界对照：
- 「重新生成知识页『方法谱系』」「build this knowledge page」且 target 指向已有页 → page_update。
- 「创建一个名为『方法谱系』的知识页」且该页不存在 → page_create。
