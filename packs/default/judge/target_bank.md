# Instructions
动作已经确定，现在选择操作的目标记忆库（Bank）。候选库在 state.ground_truth.available_banks 中，每个库带有 id（短名）、access、retain_mode 与 description（职责描述）。选项的依据就是各库的 description。

职责划分原则：
1. **显式点名优先**：如果指令明确写明了某个库的名字（例如短名 vault、archive、agent-testrole，或指明「归档库」），坚决选对应的库。
2. **归档库（archive）严格排他**：只有在指令明确写了「归档库」或明确说明查阅「已冻结的归档资料」时才选 archive。普通的「以前/历史记录/过去的决定/哪次提交/以前讨论过」是当前项目的开发演进事实，归当前项目库，绝不要把普通历史问句投到归档库！
3. **工作记忆库（agent-<role>）的专属职责**：凡是涉及**本角色的工作过程、工具使用心得与经验、插件使用探索、调试排错流水、测试尝试与测试记忆**，坚定归入该角色的工作记忆库（agent-<role>）。即使没有显式点名库名，只要内容是工具使用心得、测试记录或角色探索，就归工作记忆库。
4. **主知识库（vault）**：存放客观的**学术论文要点、算法原理、系统架构设计规范、领域业务结论**。除工具心得与测试流水归 agent 库、归档资料归 archive 库外，其他常规项目知识与操作默认归主知识库。

边界对照：
- 「查一下当时选定的 embedding 模型是什么」「哪次提交把向量扩展换成了 vchord」「历史上 retry 队列的目录名是什么」→ vault（当前项目事实与演进历史，绝非 archive）。
- 「查一下归档库里关于 embedding 的结论」→ archive（明确点名归档库）。
- 「创建一个名为「工具面心得」的心智模型，用来沉淀 omp-hindsight 插件的使用经验」→ agent-testrole（工具使用心得，坚定归工作记忆库）。
- 「把一条测试记忆写进 test-vault bank：这是 testrole 的第一次入库尝试」→ agent-testrole（测试探针与流水）。
- 「记一下 SDANet 这篇论文的要点」「把一条论文精读结论写进 vault bank」→ vault（论文客观知识）。
